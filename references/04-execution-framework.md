# 执行框架：从"跌到哪买"到"什么证据配多少仓位"

本文件是深度报告的落点。前面所有分析都必须收敛到这里，否则报告只是一篇评论。

## 一、先直接回答 Phase 0 的命题

**格式**：一句"充分/不充分/成立/不成立"，然后 3 条理由**按重要性排序**，每条都要带数字。

示例：
> **不充分。** ① 便宜的口径不可靠——PE 26.91 的分母中约六成缺乏现金支撑（经营现金流/净利 0.35–0.40）；② 相对价值是唯一无争议的强信号，但它只回答"比什么便宜"，不回答"该不该买"；③ ERP 仅 2.08%、股息率低于国债，不构成安全垫。
> 因此本框架**不把估值当作建仓理由，只把估值当作仓位系数**。理由必须来自逻辑验证。

最后一句是关键设计原则：**估值定"扣扳机的资格"，逻辑定"给多少子弹"**。

## 二、逻辑条件的可观测定义

| 编号 | 条件 | 可观测阈值 | 当前状态 | 权重 |
|---|---|---|---|---|
| C1 | 现金流缺口收敛 | 权重股合计「经营现金流/净利润」连续 2 季改善且最近一期 ≥ **0.6** | 0.35–0.40，未满足 | 高 |
| C2 | 存货增速回落至营收增速以下 | 三巨头存货同比 < 各自营收同比，持续 1 季 | +119%/+164%/+278% vs +34%~+73%，未满足 | 高 |
| C3 | 量价方向止跌 | 年降收窄至 ≤ **−5%**；采购量回升至 ≥ **400 万颗** | −10% / 250 万颗，未满足 | 中 |
| C4 | 盈利修正转为一致上修且不依赖单一个股 | 上修家数 ≥ 下修家数，且龙头以外权重股合计变动 ≥ 0 | +5.30% 但由单一个股独撑，未满足 | 中 |
| C5 | 产业资本转为净增持 | 近 3 月净增持/净减持家数比 ≥ **1.0**；或权重股回购注销单季 ≥ 50 亿 | 比值 0.16；回购注销已实施 105.6 亿，部分满足 | 中 |

**阈值必须给依据**（不能拍脑袋）：
- C1 的 0.6：现金流量表"健康"水平应接近 1.0（利润全额变现），0.6 是"缺口开始收敛而非一次性反弹"的最低证据线——属设计判断，**未做历史分布校准**（要明说）。
- C3 的 −5% / 400 万颗：来自产业现状（−10% / 250 万颗）与"降价换量重新可行"的推理。
- C5 的 1.0：多空平衡的天然分界。

## 三、目标仓位由风险预算推导（不是拍脑袋）

**不要直接说"建议 10% 仓位"**，要从相关性算出来：

```
σ_portfolio = sqrt( (w1σ1)² + (w2σ2)² + 2·w1·w2·σ1·σ2·ρ )

例：w1=0.12, σ1=0.36（标的）；w2=0.10, σ2=0.39（相关标的）；ρ=0.86
σ_p = 7.93%  →  等效单一标的仓位 = σ_p / σ1 ≈ 22%
```

| 标的 | 相关标的 | 合计 | 风险贡献（年化） | 等效单标的 |
|---|---:|---:|---:|---:|
| 2% | 10% | 12% | 4.53% | 12.6% |
| 7% | 10% | 17% | 6.20% | 17.2% |
| **12%** | **10%** | **22%** | **7.93%** | **22.0%** |
| 15% | 10% | 25% | 8.98% | 24.9%（超限） |

→ 得出**硬约束**：两标的合计 ≤ 22%。这条约束**优先于所有加仓条件**，触发即冻结。想加一个必须先减另一个——是零和的仓位调换，不是新增风险预算。

## 四、分档结构（六档范式）

| 档位 | 名称 | 仓位区间 | 单档增量 | 触发核心 |
|---|---|---|---|---|
| A1 | 便宜档 | 0 → 2% | +2% | 价格 + 时间（不需逻辑验证） |
| A2 | 深度便宜档 | 2% → 4% | +2% | 价格更低 + 时间更久 |
| L1 | 逻辑初证档 | 4% → 7% | +3% | 满足 ≥2 条（含至少 1 条 C1/C2） |
| L2 | 逻辑确认档 | 7% → 10% | +3% | 满足 ≥3 条**且必须含 C1** |
| L3 | 情景确认档 | 10% → 12%（至 15% 需情景 A 验证） | +2% | 情景 A 领跑指标成立 |
| 减仓 | — | 按失效条件 | — | 见 §七 |

设计要点：
- **A 档只依赖价格与时间**（因为这两项可观测、不依赖逻辑判断），L 档必须挂逻辑条件。
- 核心仓位（过半）必须绑定影响最大的条件 → **L2 必须含 C1**，这是硬约束。
- 档位数 6 左右：太少无法分散时点风险，太多执行成本过高。

## 四之二、底仓分档用"σ 位置"而不是"ERP 绝对值"

一个常见错误是把底仓写成"ERP > 5% 就满仓、< 3% 就空仓"。**这个写法会随利率中枢整体漂移而失效**：10Y 从 2.7% 降到 1.6%，ERP 什么都不做就白涨约 1pp（≈0.9σ），旧阈值立刻变成"永远便宜"。

正确做法是挂**相对自身分布的偏离**：

| ERP 的 z 位置 | 含义 | 底仓 |
|---|---|---:|
| z ≥ +1.5σ | 极端便宜（历史 5% 分位以内） | 15% |
| +1.0σ ≤ z < +1.5σ | 显著便宜 | 12% |
| 0 ≤ z < +1.0σ | 略便宜（**多数时间都在这一档**） | 9% |
| −1.0σ ≤ z < 0 | 略贵 | 6% |
| z < −1.0σ | 贵 | 0% |

三条使用约束：

1. **z 的 μ/σ 必须用实测滚动窗口**（近十年），不能用当期值反推——反推的 μ 会把当期 ERP 强行拉到"均值"，z 恒等于 0，整套模型失去信息。
2. **z 落在 ±0.5σ 内属临界区，不许单独作为决策依据**。必须做口径归因（PE 贡献 vs μ 贡献，见 `references/08` §三），并与其他参照系交叉验证。
3. **底仓只是"允许持有多少"，不是"应该买入多少"**。真正加仓要过 A/L 档的价格与逻辑条件——**σ 位置提供资格，逻辑验证提供增量**。

> 如果报告里同时用了 k_V（PE 绝对值折扣）和 σ 分档，必须说明二者关系：k_V 是**单次加仓的折扣**，σ 分档是**总底仓的上限**，两者不叠加成乘数，否则会双重惩罚同一个"便宜"信号。

## 五、价格档：只作资格门槛

| 价格档 | 点位 | 距当前 | 依据（带来源标注） |
|---|---:|---:|---|
| P0（已满足） | ≤ 2,450 | 0%~+1.5% | PE 近十年 4.90% 分位；比价 0.25% 分位 `[分位]` |
| P1 | ≤ 2,300 | −4.7% | 破位后再跌中位 −15.8%（本轮已达）`[统计]`；第一支撑带下沿 |
| P2 | ≤ 2,130 | −11.7% | 第二支撑带；盈利 −10% 且 PE 维持 → 2,172 `[情景]` |
| P3 | ≤ 1,900 | −21.3% | 情景 C 中枢 1,905 `[情景]` |
| P4（尾部） | ≤ 1,780 | −26.3% | 极限支撑；**P4 只减仓不建仓** |

**明确写**：价格档只提供"每档最多加多少"，不提供"必须加多少"。若价格到了但时间条件未到，该档只释放 50%。

## 六、三折扣系数与统一公式

```
本档实际增量 = 单档标称增量 × k_T × k_L × k_V
```

**时间折扣 k_T**（处理"历史中位等待期"与"已过时间"的距离）：

| 条件 | k_T |
|---|---:|
| T < 20 交易日 | 0.5 |
| 20 ≤ T < 50 | 0.75 |
| T ≥ 50 | 1.0 |
| 出现技术确认信号 | +0.25（上限 1.0，**不可多次叠加**） |

技术确认信号示例（三项满足其一）：日线收盘站上 MA20 且 MA20 走平/上翘；周线放量长下影 + 次周不破低点且量能 ≥ 20 日均量 1.3 倍；MACD 柱体连续 5 日红且 DIF 上穿 DEA。

**逻辑折扣 k_L**：逻辑未验证 0.5 / 满足 1–2 条 0.75 / 满足 ≥3 条 1.0
**估值折扣 k_V**：PE ≤ 当前值 1.0 / 当前值–30 倍 0.9 / > 30 倍 0.75

**代入示例**（必写，让读者能复核）：
> 当前 N_price=1（仅 P0 满足）→ 基础 2%；n_logic=0 → 逻辑加仓 0；k_T=0.5、k_L=0.5、k_V=1.0。
> 实给 = 2% × 0.5 × 0.5 × 1.0 = **0.5%**，其余 1.5% 冻结至 T ≥ 20 或技术确认。

## 七、失效条件：不设固定百分比止损

**为什么**：本轮下跌本身就是估值压缩（贡献 120.8%），固定 −15% 止损会在"越跌越便宜"的阶段被反复触发，把仓位割在最低点。改用**逻辑失效止损**——只有盈利/现金流证据被证伪时才卖。

| 层级 | 含义 | 条数 | 示例 |
|---|---|---:|---|
| S | 暂停建仓（冻结不卖） | 4–5 | 板块经营现金流同比 < −20%；单周跌幅 > 8% 且周量 > 前 4 周均量 1.3 倍；合计仓位 ≥ 上限；护盘政策退出 |
| R | 减仓 | 4–5 | 盈利预期由 +5.30% 转为 ≤ −5% → 减至 4%；龙头订单能见度表述下修 → 减 3%；capex 指引下修 > 10% → 减至 5% |
| X | 清仓 | 3–5 | 点位 < 极限位且盈利负增长；现金流/净利 < 0.2 连续 2 季；系统性信用事件；情景 C 领跑指标 ≥ 4/5 成立 |

每条 R/X 都要**写明确切的仓位去向**（减至 X%、减 Y 个百分点），不能只写"减仓"。

## 八、与旧框架对照（说明为什么重建）

7 维度对照表：触发变量 / 仓位结构 / 现金流 / 时间处理 / 情景联动 / 组合约束 / 失效机制。

并**点出旧框架失效的隐性原因**：
> 旧框架"点位触发即加仓"的结构，与使用者"拒绝在信号边界一次性满仓"的纪律内在冲突。**框架结构与使用者的交易习惯不匹配，是旧框架失效的隐性原因。**

一句话对比模板：旧框架回答"跌到哪里买"，新框架回答"**什么证据出现了，才配得上多少仓位**"。

## 九、周度监测协议

| # | 监测项 | 阈值 | 对应条件 |
|---|---|---|---|
| H1 | 权重股经营现金流/净利润（合计） | ≥0.6 改善 / <0.4 恶化 / <0.2 清仓 | C1（占风险 68%） |
| H2 | 2027E 一致预期及上修/下修家数 | 上修 ≥ 下修；±5% 为分界 | C4；R1 触发器 |
| H3 | 产业量价（年降、采购量、订单能见度） | 年降 ≤−5%；采购量 ≥400 万颗 | C3；R2 触发器 |
| H4 | 需求源头 capex 与 FCF | 指引下修 >10% → R3；FCF 转正 → A 加分 | A 情景领跑（**优先级高于标的自身数据**） |
| H5 | 估值与比价 | 比价分位是否维持 | 价格档；R4 触发器 |

**每周动作协议**（把监测转成动作，不能只看不动）：

```
更新 H1–H5 → 代入三个数字（N_price、n_logic、P_A）→ 算 W*
W* − W_现 ≥ 2%      → 执行加仓（单次 ≤ 档位增量 50%）
0.5% ~ 2%           → 小额试探
|差值| < 0.5%       → 不动
W_现 − W* ≥ 3%      → 检查减仓条件
```

加一条**越级规则**：H1 或 H2 触发阈值时当天重新研究，不等周例会。禁止用"点位到了"替代监测——风控全部建立在前瞻指标上，价格只是执行刻度。
